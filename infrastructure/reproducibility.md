# Reproducibility

**Date:** 2026-09-08

**Standard:** a competent third party with this repository and the recorded environment should be
able to regenerate every reported number, or to determine precisely why they cannot.

---

## 1. Configuration, not code

All experimental parameters live in version-controlled YAML under
`infrastructure/configuration/`. Code reads configuration; it does not embed parameters.

Prohibited: magic numbers in scripts, thresholds set inline, seeds hard-coded at call sites,
"temporary" parameter overrides that survive a commit.

Every configuration file is hashed (SHA-256) and the hash is recorded in the experiment registry
entry, so a config edited after a run is detectable.

---

## 2. Run record

Every significant run writes a `run_manifest.json` alongside its output:

```json
{
  "experiment_id": "EXP-0005",
  "run_id": "EXP-0005-r00042",
  "git_commit": "<40-char sha>",
  "git_dirty": false,
  "configuration": "infrastructure/configuration/exp0005_pilot.yaml",
  "configuration_sha256": "<sha>",
  "dataset_ids": ["DS-0004"],
  "random_seeds": {"scenario": 1042, "sensor_noise": 21042, "init": 31042},
  "environment": {
    "python": "3.12.x",
    "lockfile_sha256": "<sha>",
    "platform": "Windows-11-x86_64",
    "cpu": "<model>",
    "blas": "<impl and threads>"
  },
  "execution": {
    "started_utc": "...",
    "finished_utc": "...",
    "wall_seconds": 0.0,
    "output_bytes": 0
  },
  "code_version": "aura 0.1.0"
}
```

`git_dirty: true` marks a result as **non-reproducible** and disqualifies it from any confirmatory
claim.

---

## 3. Seeding

- Seeds are **explicit and hierarchical**: a base seed per experiment, derived deterministically
  into per-run and per-component seeds (scenario, sensor noise, initial conditions, model init,
  ensemble member).
- Global RNG state is never relied upon. Every stochastic component receives its own generator.
- **Determinism is verified, not assumed** (A-INF-05): EXP-0001 runs the same configuration twice
  and compares outputs bitwise. If they differ, the source of nondeterminism is found and either
  removed or documented before anything else proceeds.

---

## 4. Environment

- A dependency lockfile is committed and its hash recorded per run.
- The exact interpreter version is recorded.
- BLAS implementation and thread count are recorded — they change floating-point results.
- Thread counts are pinned for confirmatory runs to keep results deterministic.

---

## 5. Stochastic reporting

- Results are distributions over ≥30 seeds. A single run is never a result.
- Report median and a bootstrap interval, not just a mean.
- Seed-to-seed variance is reported alongside between-method differences, so a reader can see
  whether a difference exceeds noise.
- Cherry-picking a favourable seed is prohibited (`CLAUDE.md`).

---

## 6. Figure provenance

Every final figure traces:

```
Figure → analysis script + version → results file → dataset ID → configuration → git commit
```

- Figures are generated by committed scripts. **Manual editing that cannot be reproduced is
  prohibited.**
- Naming: `FIG-001-detection-performance.png`, `FIG-002-uncertainty-calibration.png`, …
- Each figure has a sidecar `FIG-XXX.json` recording the experiment IDs, dataset IDs, script path
  and commit that produced it.

---

## 7. Verification suite

`infrastructure/validation/` holds checks that run before any confirmatory experiment:

| Check | Purpose | Failure mode caught |
|---|---|---|
| `verify_manifests` | Every dataset resolves; checksums match; parent chains reach RAW | Silent data corruption or orphaned data |
| `verify_no_leakage` | No run ID appears in more than one split | TV-D6 |
| `verify_determinism` | Same config + seed → identical output | A-INF-05 |
| `verify_frozen` | No frozen dataset has been modified since freezing | TV-S1 |
| `verify_metrics` | Metric implementations reproduce analytically known values on the LTI model | Metric bugs (EXP-0004) |
| `verify_label_shuffle` | Chance-level performance on shuffled labels | TV-D7 shortcut leakage |

A failing check blocks the experiment. It does not produce a warning that can be ignored.
